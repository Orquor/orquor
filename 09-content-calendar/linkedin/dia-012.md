Open source vs proprietary in clinical AI — a false dichotomy that wastes everyone's time.

The real axes are different.

**Axis 1: Spec vs implementation.** Specifications should be open. Implementations should compete. The HTTP protocol is open; Cloudflare and AWS compete on serving HTTP. The ACTO specification is open; vendors will compete on serving ACTO well.

**Axis 2: Eval set vs production system.** Evaluation sets should be open. Production systems do not need to be. A hospital procurement team should be able to run any vendor against the same eval set and compare numbers. The system that produced those numbers can remain proprietary — it has to be, in regulated industries, because liability requires a single accountable party.

**Axis 3: Verifier methodology vs verifier suite.** The methodology of designing outcome-based verifiers should be open — that is a research contribution. A specific verifier suite tuned for a specific clinical workflow can be proprietary, because each suite encodes proprietary insights about which failure modes matter at that hospital.

**Axis 4: Audit primitive vs audit consumers.** The cryptographic audit-log format should be standardized and open. The tools that consume those logs — analytics, alerting, regulatory reporting — can be either, depending on the buyer's preference.

Orquor is publishing the ACTO spec openly. We are publishing the verifier methodology openly. We will publish the public eval set openly within twelve months. We will not publish our production-tuned verifier suite, our specific model weights, or our customer audit logs. Those are not the things that should be open.

The framing "open source vs proprietary" is too coarse to make procurement decisions with. Ask vendors which of the four axes they are open on. The answer tells you whether they understand what is at stake.
