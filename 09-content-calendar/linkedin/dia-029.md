Cryptographic timestamping in practice: how Orquor Clinical audit log entries are anchored to the Bitcoin blockchain via OpenTimestamps, and why this changes the legal posture of clinical AI.

The problem. An audit log entry — "V2 failed, dosage mismatch, escalated to human interpreter at 14:32:07 UTC" — is a string in a database. A database record can be modified by anyone with write access. A timestamp in a database can be backdated. If a translation error leads to litigation, the integrity of the audit log is contestable.

The solution. Each audit log entry is hashed. The hash is submitted to the OpenTimestamps calendar service, which aggregates hashes into a Merkle tree. The Merkle root is anchored to the Bitcoin blockchain in a single transaction. The result is a cryptographic proof — a .ots file — that the log entry existed at or before the blockchain timestamp and has not been modified since.

The workflow.

```
1. Orchestrator writes audit entry to local log.
2. Log daemon hashes the entry (SHA-256).
3. Hash submitted to OpenTimestamps calendar.
4. Calendar returns pending attestation.
5. Within ~1 hour, Bitcoin block confirms.
6. OTS proof file stored alongside log entry.
7. Verification: `ots verify entry.ots` confirms
   immutability with Bitcoin block height reference.
```

The code. The core integration is approximately 30 lines.

```python
from opentimestamps import OpenTimestamps
import hashlib

def timestamp_audit_entry(entry: str) -> str:
    """Hash audit entry and submit to OpenTimestamps."""
    entry_hash = hashlib.sha256(entry.encode()).digest()
    detached = OpenTimestamps.create_detached(entry_hash)
    # Submit to calendar; blocking call returns once
    # the calendar server has accepted the hash
    OpenTimestamps.stamp(detached)
    ots_path = f"/var/orquor/timestamps/{entry_hash.hex()}.ots"
    detached.serialize_to_path(ots_path)
    return ots_path
```

The verification is independent. A regulator, a court, or an external auditor can run `ots verify` against the .ots file and confirm that the entry existed at the claimed time. The verification does not require access to Orquor infrastructure. It requires the .ots file and a connection to a Bitcoin node.

What this means legally. The audit log is no longer a database that Orquor controls and a plaintiff can challenge. It is a set of cryptographically timestamped, publicly verifiable records. Contesting the integrity of the log requires contesting the integrity of the Bitcoin blockchain — a much higher evidentiary bar.

The cost. Each OpenTimestamps attestation costs approximately 0.00001 BTC (~USD 0.85 at current prices) in the aggregated calendar model. For a hospital processing 60 clinical encounters per day with an average of 200 logged events per encounter, the daily cost is approximately USD 10.20. Annualized: approximately USD 3,700 per hospital deployment. The cost of a single litigation episode in which the audit log integrity is successfully challenged: several orders of magnitude higher.

The architectural principle is the same one that applies to verifiers: build the forensic primitive at the architecture stage, not the litigation stage.
