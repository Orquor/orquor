How we built the Orquor Clinical verifier suite. 60 tests. 9 clinical specialties. Six months from blank repo to production.

Step one: enumerate the failure modes that actually matter. Not "the translation is wrong" — that is a category, not a failure. The first deliverable was a taxonomy:

- Dosage value mistranslation (catastrophic, weight +5)
- Dosage unit substitution (catastrophic, weight +5)
- Drug name swapped for unrelated drug (catastrophic, weight +5)
- Privacy leakage of a name from the exclusion list (catastrophic, weight -5)
- Register mismatch — formal output where simplified was requested (moderate, weight +2)
- English clauses surviving in Spanish output (moderate, weight -3)
- Truncation under length threshold (moderate, weight +1)
- Whisper hallucination on long silence (catastrophic when present, weight -5)
- Negation flip — "no fever" translated as "fiebre" (catastrophic, weight +5)

Each taxonomy entry became one or more pytest tests. The tests are atomic by rule — one check per test, no conjunctions. The weight is signed: positive for "the desired property is present", negative for "the disallowed property is absent".

Step two: build the ground-truth dataset. We started with 200 utterances, paired with gold-standard transcriptions and translations from two independent certified medical interpreters. When the two interpreters disagreed, a third arbitrated. The dataset is now 1,400 utterances and growing by 50 per week.

Step three: integrate the tests into the orchestrator. Every translation output now runs through the suite before reaching the screen. Outputs failing critical verifiers route to a human interpreter; outputs failing moderate verifiers route to the secondary model with the failure signal as feedback.

Step four: version everything. Each verifier carries a version number. The audit log records which version of the suite evaluated which utterance. Five years from now, a forensic auditor can replay every clinical decision against the exact verifier suite that gated it on that day.

This is not novel computer science. It is the methodology that already governs the most demanding agent-evaluation pipelines in the industry. The novelty is bringing the discipline to clinical AI and being willing to publish the spec openly.

If you build clinical AI without verifiers, you are not building clinical AI. You are building a clinical wish.
